# 작은 VM P-code 분석 결과

현재 ELF `de3a9064af955bd59b342b9fff0273efded539bb22e68e460c27328df7b09f0a`에 대한 Ghidra 12.0.4 Low P-code Bundle에서, 네이티브 루프 cutpoint `0x401410`으로 시작하는 **서로 다른 관측 경로 11개**를 추출했다. 추출 중 419개 네이티브 명령과 2,952개 P-code 연산을 재생했고, 각 명령의 실제 레지스터·메모리 결과와 대조했다. 요약은 [`r4vm_paths.json`](../summaries/r4vm_paths.json), Bundle은 [`r4vm_bundle.tar.gz`](../artifacts/r4vm_bundle.tar.gz), 학습 추적은 [`r4vm_training_paths.tar.gz`](../artifacts/r4vm_training_paths.tar.gz)에 있다.

| 분석 | 지정 입력 | pass | 허용된 `unknown` | 훈련 외 입력 pass |
|---|---:|---:|---:|---:|
| 새 R4VM P-code 경로 분석 | 30 | 28 | 2 | 27 |
| 기존 Lua 경로 요약의 이전 검증 기록 | 9 | 9 | 0 | 7 |
| 합계 | 39 | 37 | 2 | 34 |

R4VM의 `pass` 28개는 숫자 전이 26개와 실제 오류 경로 2개다. 숫자 전이는 결과값, 다음 VM PC, **순서 있는 슬롯 쓰기**까지 맞았다. `VMT009`는 정수 태그 검사 실패를 `type_error`로, `VMT011`은 잘못된 분배를 `bad_opcode`로 판정했다. `VMT010`의 네이티브 `opaque_add` 호출을 모델링하지 않았으므로 두 입력 모두 숫자를 만들지 않고 `unknown`을 반환했다. 이 두 건은 성공적인 계산에 포함하지 않는다. 사례별 판정은 [`combined-grade.json`](combined-grade.json), 원시 예측과 적용 경로 ID는 [`combined-analysis.json`](combined-analysis.json)에 있다.

같은 `ADD` P-code 경로 ID `347cd71f1ec34c41`가 `VMT001`의 `+7`, `VMT002`의 `+11`, 슬롯이 다른 `VMT003/004`, 두 번 같은 슬롯에 쓰는 `VMT008`, 루프 `VMT012`에 적용됐다. `VMT004/008`에서는 같은 경로 ID를 연속 두 번 사용했다. `VMT012`에서는 조건부 분기 요약을 3회 반복해 종료까지 합성했다. 테스트 샘플의 바이트코드 내용을 기준으로 새 요약을 추출하거나, 실행기를 불러 정답을 읽지 않았다. 평가 입력은 벤치마크 실행기가 전달하고 분석기는 동결한 요약·ELF·바이트코드·입력만 읽는다.

훈련 입력 `5`는 지정 평가 집합 밖이다. `VMT007`의 0 분기 경로에는 입력 `0`을 훈련으로 사용했고, 매니페스트에서 이를 `seed`로 표시했다. Lua 9건 중 `seed` 2건과 `holdout` 7건은 **기존 Lua 도구의 이전 결과**를 가져온 것이다. 이번 R4VM 분석기를 Lua에 적용해 성공한 결과로 해석하면 안 된다.

## 아직 증명하지 않은 것

- 루프 cutpoint는 ELF 주소 힌트이고, 초기 VM 상태는 학습 실행의 스택 스냅샷에 새 입력과 바이트코드를 넣어 만든다. VM 경계 자동 발견과 실행기 진입 인자부터 초기 VM 상태까지의 P-code 연결은 아직 없다.
- `output` 호출 인자와 write log 배치는 이 ELF에 맞춘 평가 adapter다. 별칭 없는 메모리 영역의 보존, 코드 버퍼 비변조, 모든 가능한 경로의 guard 완전성은 정적으로 증명하지 않았다.
- 11개 요약은 관측한 네이티브 경로의 **조건부 후보**이며, 39건 통과는 지정 샘플에서의 차등 검증이다. 다른 컴파일러, 최적화 수준, 입력 형식, VM 엔진에 대한 보장은 없다. ELF가 바뀌면 해시 검사로 기존 요약 적용을 거부한다.
- `daasdmlkas`에서는 Bundle exporter를 사용했다. 그 저장소의 backward slice/SSA 그래프를 이번 전이 추출기에 직접 연결하지는 않았다. P-code 재생과 식·메모리 버전 평가는 R4interpreter 코드에서 수행했다.

이 결과는 `ADD` 하나만 손으로 늘리는 방식보다 진전했다. 산술, 이동, 분기, 오류, 반복을 **같은 P-code 식·메모리·조건 적용기**로 처리했다. 다음 관문은 수동 경계와 상태 투영을 실제 P-code/SSA 증거에서 일반화하고, 미모델링 호출을 요약한 뒤, Lua도 이 동일 추출 경로로 처리하는 것이다.

# 전체 로직 복원 전 경로 IL과 남은 의무

## 이번에 구현한 범위

대상은 고정된 CPython 바이너리·`branchCall(x) → addFive(x)` bytecode와 세 전체 네이티브 추적(`x=251,252,254`)이다. [경로 IL](evidence_program_path_il.json)은 **공통 구조의 증거 포함 보고 형식**이다. 언어별 코드 없이 구간, 진입·종료 상태, 바이트 메모리 버전, 순서 있는 효과, 제어 edge를 기록하는 부분은 [공통 코어](common_program_path_il.py)에 있다. [Python 연결기](build_evidence_program_il.py)가 컷포인트와 기존 동결 요약·증명서를 연결한다. 값 DAG의 `X+5`는 실행 가능하지만 이 경로 IL 전체가 네이티브 프로그램을 독립 실행하는 것은 아니다.

| 구간 | `251` | `252`·`254` | 검증 등급 |
|---|---:|---:|---|
| 호출자 시작부터 외부 호출 직전 | 513명령 | 513명령 | 고정 실행기 ELF 바이트의 P-code 연속 재생. 관측 입력에서 모든 읽기·순서 있는 쓰기·종료 GPR/플래그 대조 |
| libc 벡터 호출 | 12명령 | 12명령 | **불투명**. 실제 호출/복귀, ABI 보존과 읽기·메모리 변화만 관측. 다른 입력의 의미 계약 없음 |
| libc 복귀부터 숫자 구간 직전 | 158명령 | 158명령 | 앞 구간 메모리에 관측 libc 변화를 적용한 뒤 P-code 연속 재생. libc 후 GPR·플래그는 관측 추적에서 받음 |
| 숫자 구간 | 캐시 116명령 | 할당 146명령 | 기존 동결 native 전이 적용 |
| 다음 구간 | 94명령 | 94명령 | 계산된 상태·바이트 메모리를 넘겨 기존 동결 전이 적용 |
| 호출자 반환 | 94명령 | 94명령 | 이전 종료 상태로 P-code 재생, 모든 읽기·쓰기·종료 상태 대조 |

각 경로의 모든 네이티브 명령은 정확히 한 구간에 속한다. 각 행의 후속 PC·레지스터 상태와 모든 관측 메모리 접근을 따라가며 바이트 버전을 대조했다. 값이 바뀌었는데 추적기의 쓰기 비트가 없는 **64바이트 마스크 벡터 연산**도 버리지 않는다. 바뀐 6바이트는 관측 변화로 기록하고 전체 64바이트 범위는 가능한 쓰기 범위로 남겼다. 이는 마스크 의미나 객체 별칭을 증명한 것은 아니다.

기존 [남은 범위 실험](PYTHON_REMAINING_SCOPE_RESULT.md)의 국소 호출 인자 연결, 첫 숫자 전이와 다음 전이의 합성, 바깥 반환 검증을 다시 실행하고 해시와 결과를 확인한다. 새로운 [앞부분 연속 재생](probe_connected_python_prefix.py)은 먼저 513명령을 계산한다. libc 구간의 읽기가 그 계산된 메모리와 실제 입력에서 일치하는지 확인하고, 관측된 메모리 변화와 복귀 상태를 명시적으로 받아 158명령을 이어 계산한다. **libc 복귀 상태는 계산된 것이 아니다.** 또한 앞부분 종료 메모리는 숫자 전이의 최초 메모리로 직접 전달되지 않았다. 그 경계는 관측 상태와 메모리 ledger의 연결이며 계산된 전이 합성이 아니다. 이 두 의무가 전체 symbolic 경로를 막는다. P-code 변환에서는 `vpbroadcastb`와 마스크 `vmovdqu8`가 `CALLOTHER`로 남는다.

## 복원 판정 계약

입력값만 같으면 같은 경로라고 가정하지 않는다. `252..256`의 분기 반대 방향 불가능성은 원본 `252`의 나머지 진입 레지스터·allocator/TLS 메모리·선행 경로 조건을 고정한 결과다. [앞부분 분기 작업 목록](python_prefix_branch_worklist_result.json)은 첫 513명령의 네이티브 조건분기 **60회**에 대해 `X=251..256`에서 prefix-only 반대 방향 `unsat` 증명서를 연결한다. 각 증명서에 P-code guard 순서를 보존하고, 별도로 남는 내부 조건 2개가 `cmov`에서 나온 것인지 확인한다. 이 증명은 선행 경로로 해당 분기까지 도달한 경우의 반대 edge 불가능성을 말하며, 범위 안의 모든 입력이 그 분기에 도달한다는 증명은 아니다. 숫자·이웃 240명령에는 **32회**의 별도 증명서를 붙였다. 전체 세 추적의 조건분기 반대쪽 중 여전히 열려 있는 항목은 **271회(추적별 발생 횟수)**이고, 서로 다른 PC·후속 주소 쌍은 **107개**다. 서로 다른 진입 메모리의 다른 추적에 원본 `252`의 증명서를 자동 전용하지 않았으므로 고유 쌍 수는 그대로다. 새 입력 `251`에서 확인한 반대 경로에는 할당 경로 대신 별도 캐시 요약을 적용한다.

첫 513명령의 입력 범위를 `0..256`으로 넓히면 원본 환경 모델은 `X=0`으로 `0x5a82b0` 반대 edge를 제안한다. 저장된 독립 `0` 실행에서는 객체 태그 등 진입 환경이 달라 `0x5a8250`에서 먼저 갈라지고 제안한 PC에는 도달하지 않는다. 작업 목록은 이를 `SAT 모델, 실행 미실현`으로 기록하며 경로 완료 증거로 사용하지 않는다. 이 차이는 경로 탐색기가 입력값뿐 아니라 객체 표현과 초기 상태도 계약으로 다뤄야 한다는 직접 사례다.

세 추적의 호출에서 예외 방향은 **36회(서로 다른 PC·대상 11쌍)** 미해결이다. 별도의 제한 풀 fixture에 실패·예외 접점 관측 사례 2개가 있지만 다른 바이너리·환경이므로 이번 세 경로의 의무를 닫지 않는다. 일반 CPython 할당 경로의 범위·세대·이전 해제·소유권도 미증명이다. 따라서 객체 필드 쓰기를 `Allocate`로 바꾸지 않는다. 추적에서 처음 읽은 메모리는 각 실행의 환경값이며 다른 환경에서 같은 효과가 난다는 계약이 아니다.

| 판정 | 이번 결과 | 완료에 필요한 근거 |
|---|---|---|
| 관측 경로의 상태·효과 보존 | 통과 | 세 추적의 전 명령·읽기·쓰기·경계 검증 |
| 값 IL `X+5` | 조건부 통과 | `BV32` 계산 자체는 범위 없이 평가할 수 있다. **증명된 refinement**는 경로별로 캐시 `5..251`, 할당 `252..256`과 각 원본 환경·증명서에만 연결한다. Lua/JavaScript 증명도 별도 출처. native 효과는 별도 |
| 입력 범위의 모든 경로 | 미완료 | 선행 조건별 반대 edge, 호출·예외·반환, timeout과 실행 불일치를 관리하는 탐색 루프 |
| 의미를 보존하는 prefix 축약 | 미완료 | libc 12명령의 입력·출력·마스크 쓰기·ABI·실패 계약 |
| 객체 수명 축약 | 미완료 | allocator 경계, 크기·세대·별칭·소유권·해제 증거 |
| 실행 가능한 공통 프로그램 IL | 미완료 | 분기·호출/반환·예외·효과의 전이 의미, alias 보존, 모든 opaque 구간 폐쇄 |

따라서 현재 산출물은 **전체 로직 복원이 어디에서 막히는지 자동으로 판정하는 부분 경로 IL**이다. `value_projection_executable=true`를 `native_program_il_executable=true`로 승격하지 않는다. 이번 보고 스키마에는 독립 네이티브 실행기 자체가 없으므로 불투명 구간이 사라져도 실행형 IL 완료 판정은 나오지 않는다. [판정 결과](evidence_program_path_result.json)에 의무 수와 부정 사례가 있다. 이 부정 사례는 주로 산출물 무결성 검사이며 독립적인 의미 증명 수가 아니다. 효과 누락, 상태 단절, 분기·증명서 누락, 예외를 정상 반환으로 바꾸기, 근거 없는 할당, 값 상수·경로 요약·증명 영역·fixture 변조, 불투명 호출·마스크 변화 숨김, 혼합 비트폭, 거짓 완료 선언, 다른 fixture의 예외 증거 전용 및 실제로 확인하지 못한 SAT 후보의 승격을 거부한다.

## 이어서 구현할 순서와 합격 조건

1. **외부 호출 계약:** libc 호출 전 `RDI/RSI/RDX`, 반환 `RAX/RSP`, 64바이트 마스크 효과를 독립 모델과 비교한다. 새 입력·다른 초기 메모리에서 적용하고, 호출 실패나 다른 구현에서는 `unknown`으로 종료한다. 성공하면 불투명 12명령의 상태·메모리 출력이 추적에서 재초기화되지 않아야 한다.
2. **경로 탐색기:** 각 분기의 *직전* 조건으로 반대 edge 후보를 구하고 실제 실행으로 확인한다. 처음 갈라진 곳 뒤에는 해당 새 경로를 동결·새 실행에 적용한다. `unsat`, `sat but not observed`, `timeout`, 미지원 명령을 별도로 기록한다. 호출 반환과 예외 종료를 독립 edge로 취급한다.
3. **객체·메모리 계약:** CPython allocator의 실제 자원 범위와 generation·free/reuse 이력을 확보해 공통 수명 효과에 연결한다. alias나 소유권을 모르면 원시 쓰기를 보존한다.
4. **실행형 공통 IL:** 지금의 값 DAG와 원시 전이를 상태·메모리·제어 입출력으로 연결해 독립 실행기를 만든다. Lua·JavaScript에도 동일 스키마를 적용하고, 각 엔진의 입력 해독·객체 표현만 adapter로 둔다. 출력 동등성뿐 아니라 순서 있는 효과와 예외를 비교한다.

`daasdmlkas` backward slice는 값·주소·제어 의존 후보를 줄이는 데 사용할 수 있다. 경로 도달성, 외부 호출 의미, allocator 소유권, 예외 완전성의 증거를 대신하지 않는다. 이 저장소 밖의 코드는 수정하지 않았다.

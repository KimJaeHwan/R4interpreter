# Python 숫자 경로의 제어 의무·효과 표시·순차 합성

## 확인한 범위

고정 CPython 실행기의 `branchCall(x) → addFive(x)` 관측 추적에서 숫자 구간과 바로 다음 분배 구간을 연결했다. 기존 캐시 경로 `x=43`, 할당 경로 원본 `x=252`, **새로 수집한 전체 추적** `x=255`를 사용했다. 선택된 구간 앞 683명령과 뒤 94명령은 아직 요약하지 않았으며, 네이티브 구간을 Python 전체 함수와 동일시하지 않는다.

| 입력 | 첫 구간 | 다음 구간 | 앞 구간 결과를 사용한 연결 | 관측 결과 |
|---:|---:|---:|---|---:|
| 43 | 캐시 경로 116명령·쓰기 12개 | 94명령·쓰기 18개 | 레지스터·플래그·FS/GS·바이트 메모리 전달, 구간 사이 읽기 6곳 검사 | 48 |
| 252 | 할당 경로 146명령·쓰기 18개 | 94명령·쓰기 18개 | 동일 | 257 |
| 255 | 동결한 할당 전이를 새 전체 추적에 적용 | 동결한 다음 전이를 새 전체 추적에 적용 | 동일; 대상 P-code 재생 0회 | 260 |

두 번째 구간의 입력 레지스터와 메모리를 추적에서 **다시 초기화하지 않았다**. 첫 번째 요약의 계산된 종료 상태와 쓰기 효과를 넘기고, 두 번째 구간의 모든 관측 읽기가 그 메모리와 일치하는지 확인했다. 캐시 첫 구간도 합성용 종료 상태를 내보내기 전에 각 명령과 중간·종료 행의 FS/GS 보존을 검사한다. 다만 두 구간의 최초 읽기 메모리 중 이전 쓰기로 결정되지 않는 바이트는 **각 대상 추적의 첫 읽기 기록**으로 제공한다. 따라서 임의의 외부 메모리 환경에서 통하는 정적 합성 증명이 아니라, 저장된 추적과 요약의 순차 적용 검증이다. 다음 구간 단독 적용에서는 놓칠 수 있는 구간 사이 읽기 변조가 합성 적용에서 `unknown(composed read memory mismatch)`로 거부됐다.

## 1. 경로를 찾고 누락을 판단하기

선택한 할당+다음 구간 240명령에는 조건 분기 32개, 호출 3개, 반환 3개가 있다. 호출의 반환 주소와 `RSP` 깊이가 맞는 반환을 기록했다. 관측한 세 전체 추적에서 조건 분기 반대편은 **1개만 다른 추적에서 관측**됐고, **31개는 미탐색**이다. 호출에서 빠져나가는 예외 edge도 열거하지 못했다. 보고서의 `complete`는 `false`이다. 반대 edge가 실행 불가능하다고 판정한 사례는 없다.

이 수치는 분석한 **두 구간 내부의 조건 분기 발생 횟수**이며 고유 제어 지점의 수나 프로그램 전체 경로의 수가 아니다. 호출자 앞 683명령과 뒤 94명령, 다른 핸들러, 별도 예외 경로는 이 그래프 밖에 남는다. 기존 [Python 예외 접점 실험](NEXT_RESEARCH_UNIT_RESULT.md)은 별도의 제한 풀 fixture에서 실패·예외 확인 접점을 관측했지만, 그 증거를 이번 일반 CPython 할당 경로에 전용하지 않았다.

## 2. 효과를 안전하게 줄여 보이기

할당 구간의 18개 네이티브 쓰기를 실제 순서를 유지한 채 `OpaqueNativeWrites(13) → PyLongFieldWrites(4) → ResultSlotPointerWrite(1)`로 **표시만 묶었다**. 이웃 구간의 쓰기 18개도 보존했다. 캐시 구간은 `OpaqueNativeWrites(11) → ResultSlotPointerWrite(1)`이고, 뒤 구간의 18개 쓰기를 보존한다. 각 묶음에는 원래 쓰기의 순번과 주소·폭·값을 다시 찾을 수 있다. 쓰기 삭제는 **0개**이며, 효과 동등성을 주장하는 삭제 최적화는 아직 없다.

캐시 결과는 고정 작은 정수 캐시 객체를 가리킨다. 할당 경로의 결과 객체에는 참조계수·타입 포인터·태그·digit 쓰기가 있다. 이것만으로 일반 CPython allocator의 `Allocate`·`Free`·freshness 또는 다른 객체와의 비별칭을 증명할 수 없어 수명 효과는 `unknown`으로 남겼다. 따라서 `PyLongFieldWrites`는 객체 필드 쓰기의 표시이며 논리적 할당 명령이 아니다.

## 3. 구간을 읽을 만한 로직으로 연결하기

[생성한 텍스트](connected_python_program.txt)는 두 대체 숫자 경로에 공통인 `Y: BV32 = X+5`를 보여 주고, 경로별 객체 표현과 아직 축약하지 못한 쓰기·호출자·분배 구간을 `opaque`로 표시한다. [기계 판독 결과](connected_python_program_result.json)의 `program_il`은 같은 3노드 `BV32` 값 DAG와 경로별 `NativeTransition` 두 개, 첫 전이에서 두 번째 전이로 전달한 `state1/memory1`, 원시 쓰기 그룹, 불투명한 앞뒤 구간을 담는다. 이는 **검증 결과의 구조화된 보고 형식**이며 별도로 실행하거나 전체 프로그램과 동등성을 증명한 IL은 아니다. 값 DAG는 네이티브 전이의 값 투영이며 쓰기 효과를 대체하지 않는다. 보존을 확인한 원시 쓰기는 요약한 두 구간에 한정된다. 각 묶음의 원시 쓰기, 경계, 분기·호출·반환 edge와 미해결 의무도 연결해 뒀다. 값 식의 범위 증명은 [캐시 경로 원본 환경](common_numeric_refinement_result.json)의 `5..251`과 [할당 경로 원본 환경](unseen_python_generated_proof.json)의 `252..256`에 한정된다. 실행기는 두 증명·원본 추적·바이너리·동결 요약의 hash와 결론을 대조한다. 새 입력 `255`에서 확인한 것은 그 **한 입력의 전이 적용과 결과 `260`**이다. `255`의 다른 진입 환경 전체에서 `252..256` 범위를 다시 증명한 것은 아니다. 두 경로가 가능한 모든 진입 상태를 빠짐없이 나눈다는 증거도 없다.

새 입력 `255`에서 합성된 240명령의 **각 구간** 21개 스칼라 출력·42+27개 읽기·18+18개 쓰기·후속 주소를 각 요약과 대조했다. 구간 사이 읽기 6곳, 계산된 종료 레지스터와 FS base, 캐시 구간의 중간 GS·종료 FS를 변조한 경우도 거부했다. 총 13개 부정 사례에는 원시 쓰기 누락, 객체 필드 결합 오류, 분기·호출·예외 의무 누락, 잘못된 호출 대상·반환 주소, 거짓 경로 완전성 표시가 포함된다. 제어 의무의 부정 사례는 **보고서 무결성 검사**이며, 누락된 실제 경로를 찾아냈다는 증거로 해석하지 않는다.

현재 출력은 **전체 코드 복원이 아니라 구멍을 명시한 부분 로직**이다. 다음 합격 과제는 반대 분기와 예외 종료의 실행 가능성·도달성 검사, 진짜 객체 수명 계약, 호출자 앞뒤 구간의 요약 및 합성이다.

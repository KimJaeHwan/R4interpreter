# daasdmlkas 기반 공통 분석: 증명 조건과 단계별 실험

상태: 2026-10-21의 1단계와 제한된 2단계 완료, 전체 프로그램 복원 미완료. 이 문서와 아래의 코드·결과는 `R4interpreter`에만 저장한다. `daasdmlkas`는 읽기 전용으로 사용한다. 목표는 Lua, Python, JavaScript 및 이후의 VMP를 같은 **네이티브 상태 전이와 증거 형식**으로 분석하고, 선택한 프로그램의 전체 제어·값·효과를 읽을 수 있는 공통 IL로 내는 것이다. 원본 스크립트 문법이나 opcode 의미표는 분석기 입력이 아니다.

## 역할과 정확성 경계

`daasdmlkas`의 Bundle 수용, 정규화된 바이트 단위 SSA, backward slice, 함수 요약, 새 `operation_records`는 **어느 네이티브 연산과 입력 바이트가 결과에 관련되는지** 제공한다. 연산 기록은 피연산자 순서와 조립 범위까지 보존하므로 값 식의 후보를 만들 수 있다. 그러나 `phi`는 가능한 writer의 집합이고 CFG 선행 edge를 고르지 않는다. 값 식 하나 또는 `ite`의 guard를 `phi`에서 단독으로 복원할 수 없다. 부채, 한도 절단, 미지원 연산, 미증명 호출은 완전한 식으로 바꾸지 않는다.

R4의 경로 재생·SMT·관측 ledger는 실행된 edge의 조건, fetch/decode/dispatch와 핸들러 구간, 메모리 접근 순서, 호출의 출구를 검증한다. 기존 `native_ast_il.py`의 typed DAG와 `common_program_representation_v1.json`은 표현의 출발점이다. 공통 코어는 비트폭·메모리 버전·효과·출구를 공유하고, 언어별 어댑터는 경계와 VM 슬롯의 대응만 증명한다. 한 언어의 opcode 이름을 식 생성 규칙으로 넣지 않는다.

### 조건부 건전성 명제

네이티브 상태 `N`, 관측 가능한 VM 상태 `V`, 검증된 경계 대응 `alpha(N)=V`를 둔다. 한 네이티브 구간의 시작·끝이 확인되고, 구간의 모든 가능한 제어 edge·읽기·순서 있는 쓰기·호출·예외 출구를 반영한 전이 `T`가 있으며, `alpha`가 읽고 쓰는 위치와 코드 epoch를 보존한다고 가정한다. 그러면 네이티브의 **각 실제 한 단계** `N -> N'`은 같은 전제 아래 공통 IL의 `alpha(N) -> alpha(N')`에 포함된다. 증명은 각 P-code 연산의 폭 있는 의미와 버전 있는 메모리 갱신을 순서대로 합성하고, CFG edge의 guard로 사례를 분리하면 된다. 연속 구간은 종료 경계와 다음 진입 경계 및 live-in이 일치할 때 귀납적으로 합성된다.

이 명제는 **모든 edge가 발견됐다**는 주장이 아니다. 누락된 edge, 불투명 호출, 미증명 alias·객체 수명, 종료 미증명 루프가 있으면 공통 IL에는 `unknown` 후속을 남긴다. 이런 IL은 확인된 경로의 조건부 설명일 수 있지만 원본 프로그램과의 전체 동등성은 아니다. 전체 복원 판정에는 선택한 진입 상태 영역의 모든 도달 가능한 정상·오류·예외·호출·반복 출구에 대한 커버리지, 효과와 VM 상태 대응, 종료 또는 명시적 비종료 증거가 필요하다. 값 슬라이스만으로 쓰기를 제거해도 된다는 결론은 나오지 않는다.

### 실패해야 하는 사례

- 값이 같지만 다른 writer에서 온 `phi`를 guard 없이 단일 값으로 결정한 경우.
- `0x0` 같은 매핑되지 않은 고정 주소 접근을 유효한 메모리로 가장한 경우.
- 관측되지 않은 호출·예외·할당 효과를 비어 있는 효과 목록으로 바꾼 경우.
- 다른 바이너리 또는 JIT 코드 epoch의 요약을 검증 없이 적용한 경우.
- 한 바이트코드의 중간 cutpoint 결과를 함수 전체 반환 의미로 승격한 경우.

## 1단계: 실제 기록으로 만든 typed 식과 Lua 정적 한계

재현 명령:

```bash
cd /workspace/R4interpreter
experiments/vm-transition-testbed/.venv/bin/python experiments/interpreter-expression/bridge_daas_operation_records.py
```

스크립트는 이 저장소의 봉인된 ELF/Lua Bundle을 임시 디렉터리에 풀고, 형제 `daasdmlkas` 체크아웃의 실제 수용·정규화·연산 기록 API를 호출한다. 작은 ELF 함수의 `RAX` 기록은 `RDI`, 상수 `7`, `INT_ADD`, `COPY`의 데이터 계보를 가진다. 이를 공통 typed DAG로 변환한 식과 `(RDI+7) mod 2^64`의 부등식은 SMT에서 `unsat`다. 기록의 상수를 8로 바꾸면 반례가 `sat`이고, 기록을 절단 표시하면 번역기가 거부한다. 이 증명은 **함수 출구의 한 값**에 대한 것이며 메모리·호출·전체 상태 효과 증명이 아니다.

Lua `luaV_execute`의 실제 정수 산술 연산은 `0x417ce7:5`의 `INT_ADD`이고 8바이트 R12에 기록된다. `0x417cea:0 COPY`가 R12를 읽고, 같은 명령의 `STORE`가 그 값을 쓴다. 기존 선택 경로 증명은 이 쓰기 주소를 `RBX+16`에 대응시킨다. 초기 진단에 고른 `0x417ced`의 `INT_ADD`는 결과 저장 뒤의 주소 갱신이므로 바로잡았다. 실제 산술 연산 `1b1:417ce7:5:INT_ADD`의 함수 전체 정적 기록은 300노드, `phi` 37개, 메모리 `debt` 19개, `cut` 46개로 `unknown(truncated)`이다. 이 수치는 **300노드 예산에서의 결과**이며 더 큰 예산으로도 근본적으로 불가능하다는 판정은 아니다. R4의 기존 Lua 경로 증명은 선택된 실행에 관한 독립 증거이지 정적 기록의 부채를 소급해서 지우지 않는다.

직접적인 다음 실험은 **정적 기록을 무조건 더 크게 만드는 것보다**, 함수 내부 cutpoint의 원본 연산 키와 관측된 CFG edge를 묶어 경로별 writer를 선택할 수 있는지 확인하는 것이다. 이때 원래의 불선택 대안과 도달성·별칭·호출 의무를 별도 목록으로 유지한다. 실패하면 기존 R4의 경로별 P-code 재생을 값 계산의 주체로 두고 `daasdmlkas`는 관련 연산 후보·부채 탐지에 사용한다.

## Astra 시작 검수

Astra는 `operation_records.phi`에 선행 edge 정보가 없으므로 이를 실행형 IL로 승격하지 말고, 주소·폭·부분 바이트와 미해결 부채를 그대로 옮길 것을 권고했다. cold 경로의 ADDRESS `0x0`을 상수로 바꾸거나 임의 매핑하지 않고, 실제 Lua 내부 cutpoint를 먼저 좁히라는 의견도 반영했다. 1단계 종료 검수의 지적 사항은 결과 확인 뒤 여기에 추가한다.

## Astra 1단계 종료 검수

첫 검수에서 `root_record`에는 `place` 필드가 없어 성공할 수 없는 판정 구조, Lua 산술 지점의 잘못된 설명, 변조가 IL 빌더까지 통과하지 않는 점, 실행 가정 기록 누락을 지적했다. 명시적 출력 크기를 연결하고 작은 ELF root 형식의 양성 사례를 추가했다. 상수 변조도 IL 빌더와 재해석기를 통과시킨 뒤 반례를 확인하며, 사용한 옵션·버전·코드 해시를 기록한다. 이후 실제 Lua 산술 연산과 주소 갱신의 혼동을 다시 발견해 root를 교체했다. Astra는 새 Bundle의 `INT_ADD` → R12 → `COPY` → `STORE` 원본 P-code 연결과 재생성 기록을 다시 확인해 **1단계 통과**로 판정했다. 승인 범위는 ELF의 단일 출구 값과 Lua 정적 기록의 보수적인 `unknown` 판정이다.

## 2단계: Lua 결과 저장의 경로별 값 IL

재현 명령:

```bash
cd /workspace/R4interpreter
experiments/vm-transition-testbed/.venv/bin/python experiments/interpreter-expression/bridge_daas_lua_path_value.py
```

`bridge_daas_lua_path_value.py`는 `daasdmlkas`의 정적 의존 그래프에서 `0x417cea`의 결과 `STORE`를 거슬러 `0x417ce7:5 INT_ADD`에 도달한다. 독립적으로 읽은 R4 Bundle의 원본 P-code와 opcode·피연산자·폭을 대조한다. 그 뒤 R4가 저장한 `x0`, `x9` 네이티브 경로의 P-code를 재생해 각각의 고정된 비입력 진입 상태와 처음 읽은 메모리 바이트 아래에서 경로 조건과 저장값을 증명한다. 두 경로의 환경 식별자는 다르며 한 개의 무조건적 계약으로 합치지 않는다.

결과는 `daas_lua_path_value_il.json`에 있다. `x0`는 guard `X == 0`에서 값 `10`, `x9`는 guard `X != 0`에서 값 `X+5`의 typed DAG다. 각 DAG를 다시 SMT 식으로 읽어 원본 P-code 결과와 부등식이 `unsat`임을 확인했고, 직렬화한 DAG의 상수를 1 바꾸면 부등식이 `sat`이다. 결과 저장값과 R12, 저장 주소와 관측된 핸들러 프레임 `RBX+16`의 차이도 해당 경로 guard 아래에서 `unsat`이다. 입력 바이너리·Bundle·bytecode·trace는 이전 Lua 분기 증명서의 해시와 대조하고, 수용된 Bundle의 실행 파일 해시도 현재 바이너리와 비교한다.

이것은 **값과 저장 주소의 선택 경로 증명**이다. `RBX+0`에 입력이 놓이는 전체 전달과 태그의 의미, 저장 이외의 메모리·호출·할당·예외 효과, 다른 출구까지 이번 2단계가 모두 증명했다는 뜻은 아니다. 원래 Lua 정적 store 슬라이스는 11,753노드, 미해결 읽기 1,243개, 함수 범위 미해결 쓰기 201개이며 `complete=false`다. 따라서 `whole_program_complete=false`를 유지한다. 다음에는 이 부채를 범위별로 나누고 제어 edge·호출·효과를 합성해야 한다.

Astra는 2단계의 초기 검수에서 변조 대상이 실제 직렬화 IL인지, 현재 입력이 1단계와 동일한지 확인하라고 지적했다. 코드를 보완해 IL 상수를 변경하고 재해석했으며, 현재 `daasdmlkas` HEAD와 작업 트리, 1단계 정적 기록 해시, 수용된 Bundle의 실행 파일 해시, 이전 Lua 증명서의 입력과 trace 해시를 확인했다. 재실행 뒤 Astra의 최종 판정은 **두 고정 환경에서의 경로별 저장값 관계에 한정한 통과**였다. Astra는 산출물을 읽어 검토했으며 최종 버전을 직접 재실행하지는 않았다.

## 기반 적합성 판단

`daasdmlkas`는 바이트 단위 SSA, 메모리 의존, 호출 효과와 불완전성 표시를 제공하므로 **관련 네이티브 연산을 찾고, 요약에 필요한 입력·출력·미해결 의무를 모으는 기반으로 적합하다**. 새 `operation_records`는 정확한 단순 값 식을 공통 typed DAG로 옮길 수 있음도 보여 줬다. 반면 `phi`의 경로 선택, 간접 분배의 도달성, 효과의 순서, 메모리 별칭, 객체 수명, 예외 출구와 VM 경계 대응은 이 기록만으로 해결되지 않는다. 이를 R4의 경로·SMT·전이 IL 층에서 추가하고, 조건을 증명하지 못하면 `unknown`을 보존한다. Lua에서 드러난 미해결 수와 cold 경로의 주소 `0x0` 수용 거부는 현 입력·분석 범위의 제한을 보여 주며, 기반의 연산 추적 전체가 틀렸다는 증거는 아니다.

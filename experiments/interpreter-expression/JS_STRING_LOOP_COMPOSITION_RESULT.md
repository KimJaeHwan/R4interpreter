# JavaScript 문자열 복사 루프의 전체 전이 합성

## 실험 질문과 결론

이전 [길이별 실험](JS_STRING_LENGTH_FAMILY_RESULT.md)은 다섯 자리 문자열에서 문자 복사 식만 확인했고, 전체 네이티브 상태 전이는 `unknown`으로 남겼다. 이번에는 **세 자리 경로의 앞·뒤 구간**과 **네 자리 경로의 반복 계속 구간**을 P-code 전이로 모델링해 결합했다. 고정 Node 24.19.0 `--jitless` 바이너리에서 문자열에 Smi `5`를 붙이는 2~11자리 경로 10건의 전체 전이가 관측 결과와 일치했다. 특히 이전에 미해결이던 `"10000" + 5`도 전체 전이가 맞았다.

여기서 전체 전이는 선택한 시작·끝 경계 사이의 16개 범용 레지스터, 모델링한 플래그 5개, 네이티브 읽기 주소·값, 순서가 있는 쓰기 주소·값, 후속 주소, 출력 바이트를 뜻한다. 값 하나나 원본 JavaScript 소스를 복원했다는 뜻은 아니다.

## 구간과 반복 조건

루프 앞 187개 네이티브 명령은 세 자리 소스의 요약을 쓴다. 그 뒤 7개 명령이 한 번에 **두 문자**를 읽고 결과 객체에 순서대로 쓴다. 이 구간의 포인터 역할은 원본 주소 기반 `R11`, 결과 주소 기반 `R14`, 위치 `R12`, 끝 위치 `R8`이다.

```text
루프 진입: R12 = 15, R8 = 14 + 문자열 길이
한 번 실행: 원본[R11+R12], 원본[R11+R12+1]을
           결과[R14+R12], 결과[R14+R12+1]로 복사
           R12 = R12 + 2
계속 조건: unsigned(R12) < unsigned(R8)
반복 횟수: floor(문자열 길이 / 2)
종료 뒤: 홀수 길이에 남은 한 문자를 별도로 복사
```

실제 P-code의 계속·종료 두 분기에서 guard, 위치 증가, 읽기·쓰기 주소와 값, 기반 레지스터 보존을 기호화해 반례를 질의했다. 모든 차이 질의가 `unsat`였다. 두 번째 읽기를 앞선 쓰기가 덮지 않는 조건이 필요하다. 적용기는 소스·목적지 문자 영역이 겹치면 `unknown`으로 거부한다. 루프 횟수와 홀수 꼬리 분기는 2~11자리 범위에서 별도 SMT 반례 질의가 `unsat`였다. [기호 증명과 최초 합성 결과](js_string_loop_composition_result.json)에 질의별 결과가 있다.

## 재사용 가능한 전이 요약

소스 P-code에서 다섯 구간을 추출해 [고정 요약 JSON](js_string_loop_transition_summary.json)에 저장했다: `prefix`, `pair_continue`, `pair_exit`, `odd_tail_and_return`, `even_return`. 각 구간은 입력 레지스터·플래그·메모리, 경로 guard, 전체 출력 레지스터·플래그, 읽기 값, 순서 있는 쓰기, 후속 주소의 SMT 식을 담는다. 요약 생성 때 소스 P-code 연산 1,240개를 모델링했고, 네이티브 읽기·쓰기 목록 및 소스 경로 guard와 대조했다.

[적용기](apply_js_string_loop_summary.py)는 문자열 길이로 구간 순서를 정하고 앞 구간의 **계산된 출력 상태와 쓰기 효과**를 다음 구간의 입력으로 넘긴다. 대상 실행의 중간 레지스터는 입력으로 쓰지 않는다. 대상 네이티브 추적에서 경로 모양, 최초 읽기 메모리 값, 실제 상태·읽기·쓰기를 받아 차등 대조한다. 적용 시 소스·대상 P-code 재생은 모두 0회다. 기존 고정 경로용 공통 요약과 동일한 SMT 식 평가 방식을 쓰되, 이 반복 구간의 조합 방식은 별도 JSON 스키마 `composed-native-loop-transition-v1`로 기록했다.

| 길이 | 대상 입력 | 전체 전이 |
|---:|---|---|
| 2~4 | `37`, `251`, `1000` | 각 일치; 구간 소스와 겹치는 기준 사례 |
| 5~11 | `10000`부터 `12345678901`까지 7건 | 각 일치; 루프 조합 적용 사례 |
| 12~16 | `123456789012`부터 `1234567890123456`까지 5건 | `unknown`; 경로의 앞부분부터 달라짐 |

[고정 요약 적용 결과](js_string_frozen_loop_application_result.json)는 15건 중 **10건 일치, 5건 `unknown`, 불일치 0건**이다. 잘못된 즉값, 다른 진입 문자열 객체, 변조된 네이티브 쓰기, 변조된 명령 바이트의 네 부정 입력도 모두 거부했다. 12자리 이상은 적용 길이 계약을 먼저 거부하며, [최초 합성 결과](js_string_loop_composition_result.json)는 앞 구간의 실제 경로 모양이 달라짐을 별도로 보여준다.

## 해석 범위와 다음 일

이번 결과는 **같은 바이너리·fixture의 관측된 정상 문자열 경로**에 조건부로 적용된다. 대상 경로와 최초 읽기 메모리는 네이티브 추적에서 받는다. 모든 입력 경로의 완전성이나 임의 길이, 다른 문자열 타입·인코딩, alias가 있는 복사를 증명하지 않았다. 12자리부터는 다른 앞 구간을 새로 요약해야 한다. 객체 할당과 외부 호출의 숨은 효과까지 추상화한 범용 VM 요약도 아직 아니다.

다음에는 12자리 이상에서 갈라지는 할당·복사 경계를 찾아 같은 방식으로 추가하고, 경계 추출과 반복 구간 탐지를 자동화한다. 그 후에 alias·생존성 근거로 관측 가능한 효과만 남기는 축약과 BigInt 예외 경로를 다룬다.

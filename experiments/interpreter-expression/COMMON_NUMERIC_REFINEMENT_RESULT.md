# 공통 값 IL과 엔진별 전이의 숫자 refinement

## 연구 질문과 판정

Lua, CPython, JavaScript의 특정 네이티브 실행 경로가 모두 `X+5`를 계산한다고 할 때, 그 공통 계산만 작은 typed IL로 분리하고도 엔진별 결과 표현과 네이티브 효과를 잃지 않는가? 이번 실험은 저장된 입력 `9`의 네이티브 P-code 경로에서 결과식을 각각 추출한 뒤, 같은 값 IL 후보를 조건부로 증명했다. [기계 판독 결과](common_numeric_refinement_result.json)는 IL, 엔진별 계약, 새 입력과 부정 사례를 분리해 저장한다.

```text
입력 X: BV32, 5 ≤ X ≤ 251
Y: BV32 = X + 5
IL 노드: input X → constant 5 → bvadd
```

`5`를 세 엔진의 출력 문자열에서 복사하지 않았다. 각 엔진의 네이티브 P-code 결과를 숫자로 decode한 AST에 `X=9`를 넣어 `X+C` 후보를 얻었다. 그다음 공통 영역 **전체**에서 관측 경로 guard가 성립하고 `decode(native_result) = X+C`의 반례가 없는지 SMT로 검사했다. 세 후보는 모두 `C=5`였고 guard·값 반례 질의는 모두 `unsat`였다. `X+6`을 대신 넣은 질의는 세 엔진 모두 `sat`였다. 이는 고정 바이너리·경로·다른 진입 상태를 전제한 **조건부 값 관계**이며, 언어 전체 의미 동등성은 아니다.

| 엔진 | 분석한 네이티브 구간 | 입력 decode | 결과 decode와 확인 |
|---|---:|---|---|
| Lua | 281명령 | VM 원천 슬롯의 64비트 정수에 작은 비음수 `X`를 연결 | VM 결과 R12와 기록된 payload 쓰기가 `zero_extend32(Y)`와 같음 |
| CPython | 116명령 | 고정 입력 PyLong 객체의 32비트 digit을 `X`로 치환 | 결과 슬롯 포인터가 `Y`의 작은 정수 캐시 객체를 가리킴. 캐시 키 `10..256`의 tag·digit 247개를 확인하고, 원천 객체 alias와 경로상의 캐시 쓰기를 배제 |
| JavaScript | 23명령 | Smi 태그가 붙은 누산기의 상위 32비트를 `X`로 사용 | 결과 누산기의 상위 32비트가 `Y`, 하위 태그 32비트가 0 |

Python의 캐시 쓰기 검사는 12개 모델링한 쓰기의 **기호 주소**가 공통 영역에서 각각 관측 주소와 같다는 반례 질의가 `unsat`인지 확인하고, 해당 주소가 캐시와 겹치지 않는지 확인한다. 다른 실행 주체의 비관측 쓰기까지 증명한 것은 아니다. 입력 객체 `9`의 digit을 바꾼 기호 상태에서 결과 객체가 같은 객체로 돌아오는 경우는 공통 영역 밖이다.

## 값 IL과 전체 네이티브 효과의 경계

3개 노드의 값 IL은 **숫자 결과만** 표현한다. Python의 네이티브 읽기 31개·순서 있는 쓰기 12개·후속 주소, JavaScript의 읽기 8개·후속 주소는 기존 전체 전이 요약에 그대로 남긴다. 입력 `9`의 값 증명 추적에서 빠져 있던 명령 bytes를 고정 바이너리에서 읽어 요약의 전체 경로 hash와 대조했고, 그 **동일한 추적**에 전체 전이 적용기를 실행해 효과까지 승인받았다. Lua는 별도의 입력→VM→반환 경로 증명과 원시 추적을 보존한다. 이를 하나의 새 전체 효과 요약으로 대체하지 않았다.

| 새 관측 입력 | 값 IL 예측 | 결과 decode | 적용 근거 |
|---|---:|---:|---|
| Lua `42` | 47 | 47 | 새 경로를 P-code로 재증명하고 호출자 결과에 연결 |
| Python `43` | 48 | 48 | 기존 전체 전이 승인: 읽기 31·쓰기 12개, 대상 P-code 재생 0회. 핸들러 결과 슬롯과 호출자 출력 일치 |
| JavaScript `43` | 48 | 48 | 기존 전체 전이 승인: 읽기 8개, 대상 P-code 재생 0회. 핸들러 RAX와 호출자 출력 일치 |

Python의 네이티브 쓰기 하나를 제거하면 `unknown(ordered effects mismatch)`가 된다. 잘못된 JavaScript Smi 태그도 거부한다. `X=4`와 `X=252`는 **공통 입력 영역 자체에서 제외**되며, 이를 각 엔진의 전체 adapter가 자동으로 올바른 대체 경로에 배치한 증거로 해석하지 않는다. 기존 Python `252` 실행은 별도 할당 경로여서 저장된 캐시 전이에서는 `unknown`이었다.

## 남은 연구

이번 IL은 출력값을 3개 노드로 줄였지만 전체 네이티브 동작을 3개 노드로 축약하지 않았다. 다음 단계는 엔진별 입력·출력 decode 계약을 typed IL의 검증 가능한 인터페이스로 만들고, 다른 호출 문맥에서도 계약을 새로 증명하거나 재사용할 수 있는지 확인하는 것이다. 효과의 삭제 가능성, 새 handler의 의미 자동 발견, 일반 Python 정수·JavaScript Number·Lua overflow 경로, 호출·예외·수명 효과의 공통 의미는 남아 있다.
